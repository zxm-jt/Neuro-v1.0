## 0. 调研结论（同类 / 近似产品，6 个）

| # | 产品 | 借鉴什么 | 不借鉴什么 |
|---|------|----------|------------|
| 1 | **KDE Connect** | 手机通知**镜像**到桌面、可 dismiss / reply；系统托盘显电量 | 偏 geek 的插件式开关设置、utilitarian 外观 |
| 2 | **Pushbullet** | Material 富通知、**可从 PC 回复 SMS / WhatsApp**、自动复制剪贴板（低摩擦） | 中心化账户、付费墙 |
| 3 | **腾讯 QClaw** | 把**微信当电脑遥控器**、结果回传微信对话、**工作状态可视化**（龙虾忙碌/待机） | 像素风美术、强 AI 任务定位 |
| 4 | **cc-haha** | 微信机器人**扫码绑定 + 6 位配对码**、消息只过本机（隐私模型）、轻量遥控 | 面向开发者、术语重 |
| 5 | **Live2D 桌宠族**（OpenDesktopPet / Firefly Companion / neuro 本体） | **气泡是桌宠天然输出载体**；IDLE→SPEAKING↔REACTING 状态机；情绪系统；长文本阈值展开 | 无结构化数据展示能力 |
| 6 | **DSH Go** | 对话流内**可视化进度 / 用时 / 交付文件**（工具调用次数、结果缩略图） | 技术向、SSH 心智负担 |

**提炼的设计共识**：
- 通知/回执必须是 **actionable**（可标记已读 / 回复 / 复制 / 打开），而非只读弹窗（Pushbullet / KDE Connect）。
- 遥控的**反馈要回传原地**（微信对话 / 桌宠气泡），形成闭环（QClaw / cc-haha）。
- 桌宠的**人格化气泡**承载"短反馈、低打断"的陪伴感（Live2D 族 + 桌宠设计通用原则：回复≤80字、动画频率低、不弹大窗）。
- 结构化数据（短信列表 / 搜索结果 / 指令产出）**不该塞进气泡**——会破坏"短反馈低打断"，需要独立承载面。

## 1. 核心决策：三类能力 × 三通道呈现层级

三类能力（A 远程指令 / B 消息同步 / C 联网搜索）都有「瞬时确认」与「结构化结果」两种信息形态。据此建立 **三通道层级**，让"人格"与"信息"各归其位：

```
┌──────────────────────────────────────────────────────────────┐
│  通道 1 · 字幕 / 连接胶囊（最轻，瞬态状态）                      │
│     └ 手机连接态、同步中、指令执行中——一眼扫过即过              │
│                                                                │
│  通道 2 · 桌宠气泡（人格脸面，短反馈）                          │
│     └ 姐姐语气确认 / 播报 / 轻调侃：「已帮你打开 Chrome 啦～」   │
│       表情/动作随状态切换（思考皱眉→完成笑眼）                  │
│                                                                │
│  通道 3 · 同步面板 LinkPanel（右侧停靠，结构化持久）            │
│     └ 同步短信卡 / 指令回执卡 / 搜索结果卡——可操作、可回溯      │
└──────────────────────────────────────────────────────────────┘
```

**为什么是三通道而非全塞气泡**：调研 5 显示长文本/列表会摧毁桌宠的"短反馈低打断"陪伴感；调研 1/2 证明结构化通知需要可操作卡片。气泡只负责"人格确认"，面板负责"信息密度"，胶囊负责"瞬态状态"——三者满足 `每屏强调色 ≤2 处`（气泡用品牌粉、面板用雾蓝通道色，分属不同图层）。

## 2. 配色 / 字体 / 图标库 / 风格基调

### 图标库（明确锁定）
**`lucide`**（stroke-width 2，尺寸 16 / 20 / 24px）——与 MASTER §4.2 一致，**全项目统一，不混用**。本模块扩展的图标映射见 §6。
> P0-1 红线已满足：无任何 emoji 作为功能图标。微信侧 bot 回复是微信原生 UI 渲染，我们控制的是**文字与指令词**，不在 UI 内嵌 emoji 图标。

### 配色（延续 + 扩展，无新色相）
- 品牌锚：`--accent #FF5FA2 / #FF6FA8`（实色，非渐变——P0-2 红线特指"紫→粉渐变 + 玻璃 + 发光三位一体"，本方案零渐变）。
- 状态马卡龙（沿用）：薄荷 `#5AD1C8` / 杏黄 `#FFB072` / 珊瑚 `#FF7A6B` / 雾蓝 `#6FA8DC`。
- **新增「手机通道色」= 雾蓝 `--state-vision (#6FA8DC)`**：专用于手机连接 / 同步 / 新项指示。复用既有色相，**不引入紫→粉或任何渐变**，与状态环的粉/杏黄在时间与空间上互斥。
- 指令执行中 → 复用杏黄（thinking）；完成回执 → 复用 success `#16A34A` 勾选 + 气泡粉；失败 → danger `#DC2626` / 珊瑚。

### 字体（完全复用，零新字体文件）
- 字幕气泡：`--font-display`（NeuroSub 手写体）
- 面板 / 胶囊 / 设置项：`--font-ui`（NeuroSubBaloo 圆体 + 幼圆 CJK）——保证中文可读、与角色调性统一
- 数字（用时 / 计数）：`--font-mono` + `tabular-nums`

### 风格基调
**克制现代（chrome 对标 Linear / Notion 级秩序感）＋ 角色人格（气泡对标 QClaw 的"工作状态可视化"但用 Live2D 姐姐语气落地）**。面板用 1px 线分隔（`divide-y`）与实心 `ink-800` 底，无卡片盒子堆叠、无玻璃模糊（透明窗口下 `backdrop-filter` 失效，见 MASTER 已知坑）。

## 3. 页面 / 交互流草图

### 3.1 手机端（用户视角 · 微信原生，不重造壳）
```
【绑定】桌面端"联动"设置 → 生成二维码 → 手机微信扫码登录机器人 → 输入 6 位配对码确认（参 cc-haha）
       ↓
【日常遥控】微信发「打开 Chrome」
       微信：「已送达 ✓」
       电脑执行 → 机器人回执：「已打开 Chrome 啦～（用时 1.2s）」+ 截图/文件回传（如适用）
       
【消息同步】手机收到短信/微信 → 电脑桌宠气泡「妈妈发来短信哦，要看吗？」
       微信发「读一下」→ 机器人朗读/转写
       微信发「回复：晚点回你」→ 机器人代发并回执「已回复 ✓」
       
【联网搜索】微信发「搜一下今天 A 股行情」
       机器人：「正在搜…」
       回传结构化结果卡（标题 + 摘要 + 来源域名 + 链接）
       
【错误/边界】机器人：「没找到这个窗口呢，要我再试一次吗？」（姐姐语气，不 blame 用户）
```
指令词表（自然语言优先，快捷指令兜底）：`打开 <应用>` `/截图` `/锁屏` `搜 <关键词>` `读一下` `回复：<内容>`。

### 3.2 电脑端（桌宠接收与反馈视觉流）
```
┌────────────────────── 屏幕（透明覆盖层）──────────────────────┐
│                                              [LinkPanel 右侧停靠]│
│            Live2D 姐姐                                  │ 手机 ││
│         ┌── 状态环（贴胸口）──┐                          │ ●已连││
│         │  thinking(杏黄)     │                          ├──────┤│
│         └────────────────────┘                          │ 短信 ││
│                        [连接胶囊] ← 字幕上方             │ 妈妈 ││
│            右下角字幕条（贴底）                          │ 14:02││
│                                                       │ 搜索 ││
│                                                       │ A股… ││
└───────────────────────────────────────────────────────┴──────┘
```

**指令到达**：状态环切 thinking（杏黄虚线旋转）→ 气泡「收到～这就帮你打开 Chrome」→ 连接胶囊闪「执行中」。
**执行中**：气泡打字机「正在打开…」+ 面板任务卡「打开 Chrome · 执行中」（杏黄脉冲点）。
**完成**：状态环切 speaking（粉+脉冲波）、姐姐笑眼 → 气泡「打开好啦！」→ 面板卡转「已完成」+ 用时/结果，有文件附缩略图。
**消息同步到达**：面板滑入新消息卡（app 图标 + 发件人 + 预览 + 时间）→ 姐姐轻推面板方向 + 气泡「有新的短信哦，要看吗？」→ 用户点头/点击 → 朗读或展开。
**搜索结果**：气泡「帮你搜到这些～」+ 面板展开搜索卡（多条：标题 + 摘要 + 真实来源域名）。
**断连**：连接胶囊变灰「手机已断开」→ 气泡「手机好像走远啦，连上我再帮你～」。

## 4. 初步 Design Token 草案（C-extension，全部 token-derived）

> 不引入任何新 hex 色相；新增项一律引用既有 primitive，遵守 MASTER「组件层禁裸色值」铁律。

| Token | 值（引用） | 用途 |
|-------|-----------|------|
| `--link` | `var(--skygray)` `#6FA8DC` | 手机通道色：连接/同步/新项指示 |
| `--link-soft` | `rgba(111,168,220,0.14)` | 面板分区底 / 新到达高亮底 |
| `--panel-surface` | `var(--ink-800)` `#1E1E28` | 同步面板底（实心，不毛玻璃） |
| `--panel-surface-raised` | `var(--ink-700)` `#2A2A36` | 面板卡片底 |
| `--panel-width` | `320px` | 展开宽 |
| `--panel-width-collapsed` | `56px` | 收起为细轨（仅未读角标） |
| `--panel-gutter` | `var(--safe-gutter)` `24px` | 距屏幕右边距 |

组件级（`component.linkPanel` / `component.linkCapsule`，见 design-tokens.json）：头部高 44px、卡片圆角 `--radius-md`(12px)、卡片内距 `space-3 × space-2`、图标 16px、**卡片上限 16px 圆角（禁 ≥24px AI 过度圆滑）**。

## 8. 给前端 / 架构的提示（Agent Guide 摘录）

1. **同步面板是 Electron 透明窗口内的新 DOM 层**（右侧停靠），`pointer-events` 默认穿透，仅卡片可交互——参考 MASTER 已知坑：`js/main.js` 鼠标穿透判定需加入面板可交互区。
2. **面板底色用 `--panel-surface`（实心 ink-800）**，不毛玻璃（透明窗口下 `backdrop-filter` 失效）。
3. **状态由后端 127.0.0.1:6006 的微信通道健康度驱动**，写 `body[data-link="connected|syncing|disconnected"]`，CSS 变量驱动，零 JS 样式逻辑（沿用 MASTER 的 setState 思路）。
4. **面板与字幕/状态环避让**：面板右边缘停靠，底部预留 `--safe-gutter` + 字幕高度清场，不进入桌面中央。
5. **`prefers-reduced-motion`**：面板滑入/脉冲点循环动画全部停（沿用 MASTER 降级）。

## 11. 边界同步补充（来自架构师 §7/§13 + PM PRD 设计约束）

> 2026-11-06 收口：架构师给出 WS 事件契约 + 兜底 PWA 面板边界；PM 给出 MVP 界面清单与 P0 设计约束。本节能独立成立，全部复用既有 Token，无新色相、无渐变、无 emoji。

### 11.1 WS 事件 → 视觉映射（契约稳定，视觉由我定）
后端 `WS /v1/link/events` 推四类帧 `{"type": "...", "payload":{...}}`：

| WS type | 落地视觉 | 复用组件 | 通道色/状态 |
|---------|----------|----------|-------------|
| `sms_received` | 同步面板滑入消息卡 + 气泡播报「有新的短信哦，要看吗？」 | LinkPanel 同步消息卡 / 桌宠气泡 | `--link`（雾蓝） |
| `command_done` | 面板指令回执卡转「已完成」+ 气泡确认（角色口吻）+ 状态环 speaking | LinkPanel 回执卡 / 状态环 | speaking(粉) |
| `search_done` | 面板展开搜索结果卡（标题+摘要+真实域名，可折叠） | LinkPanel 搜索卡 | `--link`（雾蓝） |
| `bot_status` | 连接胶囊随 up/down 切 `--link-active`/`--link-idle`；down 时字幕「微信通道离线，本地功能正常」+ 状态环转 muted 灰 | LinkCapsule / 字幕 / 状态环 | active=雾蓝 / idle=灰 |

### 11.2 指令执行三态（F6，对接现有语音状态层）
| 阶段 | 复用状态 | 形状/颜色 | 桌宠表现 |
|------|----------|-----------|------------|
| 执行中 | `thinking` | 杏黄虚线旋转 | 皱眉专注 |
| 完成 | `speaking` | 粉脉冲 + 角色口吻确认 | 笑眼 |
| 失败 | `failed`（新增） | 实线环 + 轻微抖动（reduced-motion 下静止） | 摇头/无奈，气泡「没成呢，要我再试一次吗？」 |

> `failed` 复用 `--danger #DC2626`，**区别于** `interrupted`(珊瑚断弧，用户打断)。两者语义不同，颜色也区分。

### 11.3 通道离线视觉（PM #5）
`bot_status=down` → `body[data-link="offline"]`：连接胶囊转灰（`--link-idle`）+ 字幕显示「微信通道离线，本地功能正常」+ 状态环转 `muted`(灰)。**不弹大窗、不抖屏**，遵循"短反馈低打断"。

### 11.4 手机指令日志面板（PM #3，隐私去标识）
- 与「实时回执卡」分离：日志是**历史视图**，按 PM/埋点要求**不显示指令原文**，仅记类别 + 相对时间 + 状态（已执行/失败）。
- 每条：lucide 类别图标（`terminal`/`search`/`power`/`smartphone`）+ 「已执行 / 失败」+ 「3 分钟前」。无 verbatim 文本，满足 `command_executed/command_failed` 去隐私埋点。
- 实时回执卡（本人当前操作）可显示具体指令回显（用户自己知道发了什么）；日志面板一律匿名。

### 11.5 兜底 PWA 控制面板（`/pwa`，与 Token 体系一致）
- 纯功能控制台（发指令 / 触发搜索 / 看短信），**非桌宠本体**；但走同一套 Token，不出现第二套风格。
- 它是**独立不透明 web 页**（非透明覆盖层），故可用实心 `--ink-900` 背景 + `--surface` 卡 + `--accent`(粉) 按钮 + lucide 图标，与桌面端同源。
- 移动端（手机浏览器同 WiFi 访问）用响应式单列：顶部连接状态条（雾蓝→灰）+ 指令快捷按钮（白名单）+ 搜索框 + 短信列表。触摸目标 ≥44px。

### 11.6 图标命名对齐（PM #2 示例）
lucide 实名映射（stroke 2，16/20/24）：`Search`(搜索) · `Power`(电源/锁屏) · `MessageSquare`(消息) · `Smartphone`(手机) · `Terminal`(指令) · `WifiOff`(离线) · `RefreshCw`(同步中) · `ExternalLink`(打开来源)。**禁止 emoji**。

### 11.7 若后续 Android 伴随应用（F4/P1）
极简引导页：仅「开启通知使用权」「关闭电池优化」两步引导，视觉与品牌粉一致；不引入新字体/色相。
